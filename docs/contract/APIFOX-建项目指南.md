# Apifox 项目搭建指南（TeamPulse 第一阶段 / M1）

> 目标：落实《前置任务》P4-01~P4-04，把"契约冻结"从文档变成可验收的 Apifox 项目。  
> 产出：4 人可见的项目 + 6 个目录 / 32 条接口 + 本地/Mock 双环境 + 登录后 token 自动写入 + 冻结纪要 v1.0。

## 0. 现成资产

- 导入文件：`docs/contract/teampulse-m1.openapi.json`（OpenAPI 3.0.3，32 条接口、6 个 tag、每条 summary 带 `[M1]`、description 标负责人与错误码）。
- 口径：能力表 24 行 → 按 method+path 展开 **32 条**（认证 4 / 课程 4 / 项目 5 / 小组 7 / 任务 9 / 总览 3）。
- 若 Apifox 版本界面文案有差异，按同义入口找（"环境管理""导入数据""Mock 设置"）。

## 1. 建项目（A，约 3 分钟）

1. 登录 [apifox.cn](https://apifox.cn)（国际版 apifox.com），进入团队 → **新建项目**。
2. 类型选 **HTTP 项目**；名称 `TeamPulse-第一阶段`；描述填：`M1 契约冻结 v1.0；口径见 docs/contract/teampulse-m1.openapi.json`。
3. 建好后进入项目，左侧应为「接口 / 数据模型 / 环境 / 测试用例 / 文档」结构。

## 2. 拉齐四人（A，约 3 分钟）

1. 项目设置 → **成员管理** → 邀请成员（链接或账号邀请）。
2. 角色：A = 管理员；B / C / D = **编辑者**（能改接口、发请求，不能删项目/改成员）。
3. 验收：四人各自打开项目能看到同一目录树。

## 3. 建环境（A，约 5 分钟）

项目设置 → **环境管理**，新建两个环境：

| 环境   | 前置 URL                                                    | 变量                                                             |
| ---- | --------------------------------------------------------- | -------------------------------------------------------------- |
| 本地   | `http://localhost:8080/api`                               | `token`（空）、`userId`（空）、`projectId`（空）、`groupId`（空）、`taskId`（空） |
| Mock | `https://mock.apifox.cn/m1/{项目ID}`（国际版 `mock.apifox.com`） | 同上；项目建好后自动生成，复制到此处                                             |

- 后端已配 context-path `/api`，所以前置 URL 必须带 `/api`，接口路径里**不要**再写 `/api`。
- 环境变量用 `{{token}}` 形式引用；切换环境即可切本地/Mock，前端不用改代码。

## 4. 导入 32 条接口（A，约 3 分钟）

1. 左侧目录树顶部 **+ → 导入 → OpenAPI/Swagger**。
2. 选 **文件导入**，上传 `docs/contract/teampulse-m1.openapi.json`。
3. 导入模式选 **智能合并**（首次导入等同新建）；勾选 **按 tags 生成目录**。
4. 导入后核对：6 个目录、32 条接口；每条 summary 以 `[M1]` 开头。

> 手动建也不是不行，但 32 条手填约 1.5~2 小时，且路径容易拼错（如 `/tasks/board`、`/reports/project-progress`），不建议。

## 5. 目录、负责人、M1 标记（A + B/C/D，约 15 分钟）

- 目录：认证 / 课程 / 项目 / 小组 / 任务 / 总览（导入自动生成，重命名按此为准）。
- 负责人：接口详情 → 右上「负责人」→ 按模块选 A / B / C / D。
- M1 标记：已写在 summary 前缀 `[M1]`；若团队用「标签」字段，可批量打 `M1` 标签（不要用标签做目录分组，避免和 tags 冲突）。
- 接口状态：未开工设「设计中」，联调通过后改「已发布」。

## 6. Mock 设置（A，约 5 分钟）

1. 项目设置 → **Mock 设置**：开启 Mock 服务；Mock 优先级选 **响应示例**（这样才能返回我们写的示例数据，而不是随机生成）。
2. 切到「Mock」环境，对 `GET /reports/project-progress?projectId=1` 发请求，应返回 `code=200` 与本文件中的示例结构。
3. D 的前端通过 `.env.mock` 指向 Mock 前置 URL 即可开工，不必等 B/C 的代码。

## 7. 登录后自动写 token（A，约 5 分钟）

1. 打开 `POST /auth/login` → **后置操作** → 添加「提取变量」或自定义脚本：

```js
const body = pm.response.json();
pm.environment.set('token', body.data.token);
pm.environment.set('userId', body.data.user.id);
```

1. 在「认证」目录的 **目录设置 → 前置操作** 加 Header：`Authorization: Bearer {{token}}`。
2. 对 `POST /auth/register`、`POST /auth/login` 关闭目录头继承（这两个接口免登录）。
3. 验收：先跑登录，再跑 `GET /auth/me` 返回 200；把 token 改坏应返回 401 统一返回体。

## 8. 冻结纪要与版本（A，约 10 分钟）

- 纪要放仓库 `docs/contract/freeze-v1.0.md`（不要在 Apifox 里写长文）：8 项冻结逐条结论、参与人、时间、异议、变更流程、站会时间、合并窗口、M2 验收时间。
- Apifox 项目「项目概览/说明」只放三行：`契约版本 v1.0`、`纪要链接`、`变更流程一句话`。
- 变更流程：群内说明 → A 判断影响面 → 受影响方确认 → 文档升版本 + Apifox 同步 + 广播。

## 9. 验收清单（对应第 9 章 9.5，五项全绿才可放行）

- [ ] 四人能打开项目，角色为 1 管理员 + 3 编辑者
- [ ] 6 个目录、32 条接口齐全，逐条有负责人与 M1 标记
- [ ] 8 项冻结在 `freeze-v1.0.md` 有结论、有时间、有回执
- [ ] Mock 环境可对 `/reports/project-progress` 发起请求并返回示例结构
- [ ] 版本号 v1.0 已记录，变更流程已广播

## 10. 常见坑

| 现象           | 原因                               | 处理                                   |
| ------------ | -------------------------------- | ------------------------------------ |
| 所有请求 404     | 前置 URL 少了 `/api`，或路径里重复写了 `/api` | 前置 URL 保留 `/api`，接口路径从 `/auth` 开始    |
| 一直 401       | 未先跑登录 / token 变量未写入 / 目录头未生效     | 先跑 login，检查环境变量与目录前置操作               |
| Mock 返回随机数据  | Mock 优先级不是「响应示例」                 | 改优先级；确认接口有保存示例                       |
| 导入后目录是英文 tag | 导入时未按 tags 分组                    | 重新导入勾选分组，或手动建 6 个目录拖入                |
| 删除成员接口报错     | DELETE 带 body 被网关/代理丢弃           | 本地直连 8080 测；生产如遇代理需改用 POST 变体并在契约中登记 |
